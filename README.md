# 운동 노트 v7.5.5 — 펙덱·리어 델트 머신 추가


[운동 앱 열기](https://bbakki.github.io/workout-app/)

## 이번 변경

- 펙덱 플라이(푸시·가슴)와 리어 델트 플라이 머신(풀·소근육·후면 어깨)을 추가했습니다. 전체 66개 / 소근육 13개입니다.
- 사용자 보유 확인으로 등록하며 브랜드·모델은 미확인입니다. 기본 수행 5항목과 상세 가이드를 제공합니다.
- 사진 확인 기구와 사용자 보유 확인 기구의 개수를 따로 표시합니다. 기존 루틴·기록은 유지합니다.

## v7.5.4에서 유지한 가이드

- 전체 64개 운동에서 **그립 / 고정할 부위 / 힘의 방향 / 자극점 / 자세 체크**를 펼침 없이 볼 수 있습니다. 긴 세팅·반복·호흡 설명은 아래 가이드에 유지했습니다.
- 비어 있던 소근육 탭을 팔·측면/후면 어깨·종아리 **12개 운동**의 보조 분류로 수정했습니다. 푸시·풀·하체에서도 같은 운동을 찾을 수 있지만 데이터·통계는 중복되지 않습니다.
- Cybex 바이셉스 암컬을 추가했습니다. 사진의 ARM CURL·Biceps 표기와 밀기 안내·그림이 모순되어 실제 기구 동작 확인 주의문을 먼저 표시합니다.
- 기존 63개 운동 이름·ID, 루틴·기록·동기화 형식은 유지합니다. 현재 루틴을 자동 변경하거나 새 컬을 추가하지 않습니다.

## v7.5.3에서 유지한 루틴

- 측면·후면 어깨와 허벅지 앞·뒤를 우선하도록 PPL A/B를 조정했습니다. 래터럴 레이즈를 앞당기고 후면 어깨·레그 익스텐션의 기본 세트를 보강했습니다.
- Legs A/B에서 카프 레이즈를 제외하고 시티드 레그컬을 유지합니다. 카프와 라잉 레그컬은 도감에서 선택할 수 있습니다.
- 적응기에는 종목당 최대 2세트, 코어는 1세트입니다. Legs A 7세트·Push B 10세트이며 자동 증량을 보류합니다.
- 적응 후 일반 중량 운동도 최근 14일 안에 두 번 연속 같은 중량으로 모든 본세트의 반복 상한·RPE 7 이하를 확인해야 증량을 제안합니다. 같은 기구 세팅인지도 확인하세요.
- 기존 기록과 날짜별 계획은 그대로 보존합니다. 개인별 시험 중량은 동기화되는 기구 메모에서 확인하며 공개 코드에 포함하지 않습니다.

## 유지되는 기능

- 이전 일반 도감·블로그 초안·예전 루틴 선택을 제거했습니다. 현재 올데이 운동만 사용합니다.
- **관리 → 이전 운동 기록**에 검색·날짜 필터·펼쳐 보기를 제공합니다. 2026-10-18 이전 세션과 현재 올데이 도감에 없는 운동은 읽기 전용입니다.
- 원래 이름·세트·중량·당시 계획을 보존합니다. 이전 기록은 새 중량 추천·PR·통계에서 제외되며 백업과 Google Sheets 동기화에는 계속 포함합니다. 인바디·일일 체중 이력은 유지합니다.
- 가슴·등·하체 주 2회 PPL A/B를 재배분했습니다. 첫 적응 주는 4회, 첫 2주는 종목당 최대 2세트입니다. 실제 운동 순서는 요일 계획을 따릅니다.
- 운동별 상세 설명은 독립된 데이터이며 시작 자세·반복·근육 작용·주의사항으로 나뉩니다.
- 휴식 타이머는 기존 하단 184px 형태를 유지하며 한 주 운동 구성과 요일 탭을 쉽게 확인할 수 있습니다.

**배포 후 업데이트 확인:** 앱의 **새 버전 준비됨 · 저장 후 업데이트**를 누른 뒤 로고 옆 **7.5.5**, 도감 66개 / 소근육 13개를 확인하세요. 기존 사이트 데이터나 저장소를 지울 필요가 없습니다. 이번 변경에는 Apps Script 재배포가 필요하지 않습니다.

이전 `plan_v2`, `routine_profile` 값은 백업·설정 동기화 호환성을 위해 보존하지만 활성 루틴으로 사용하지 않습니다. `plan_v3`의 이전 짐 추가·교체 항목도 현재 운동에서 제외합니다. 이미 기록된 날짜의 올데이 계획은 유지하고, 이전 종목만 들어 있는 날짜별 계획에는 새 운동을 시작할 때 현재 계획을 덧붙여 원본 행을 보존합니다.

## Google Sheets 연결

기존 API v7 연결을 계속 사용할 수 있습니다. 새 설치 또는 API v6 이하에서 올리는 경우:

1. 관리의 데이터 백업에서 JSON 파일을 저장하고 Google Sheets도 사본을 만듭니다.
2. 연결된 Apps Script 프로젝트의 코드를 `apps_script.gs`로 교체합니다. 기존 `doGet`/`doPost`를 중복으로 남기지 않습니다.
3. 프로젝트 설정 → 스크립트 속성에 **`FIT_API_TOKEN`**을 설정합니다. 기존 연결키는 유지하며 새 값은 32자 이상의 충분히 긴 무작위 문자열을 사용합니다. 저장소나 배포 URL에 넣지 않습니다.
4. 배포 관리 → 기존 배포 편집 → 새 버전으로 API v7을 배포합니다. 기존 배포를 편집하면 `/exec` URL을 유지할 수 있습니다.
5. 앱의 Google Sheets 연결에서 `/exec` URL과 연결키를 입력합니다. 연결키는 기기에만 저장되며 JSON 백업에는 포함되지 않습니다.
6. 기록 차이가 있으면 원본을 비교한 뒤 적용할 쪽을 선택합니다. 시트에 없는 로컬 기록을 자동 삭제하거나 일괄 덮어쓰지 않습니다.

v7 서버는 연결키 없는 요청과 구버전 쓰기 API를 거부합니다. 다른 기기도 모두 업데이트하세요.

### 거의 모든 기록이 기기에만 있다고 나올 때

관리의 연결 진단에서 연결된 스프레드시트 ID와 탭을 먼저 확인합니다. 진단은 읽기 전용입니다. 탭 누락·헤더 불일치·잘못된 파일 연결을 해결한 뒤 다시 비교합니다. 시트의 빈 응답을 로컬 데이터 삭제로 해석하지 않으며, 기존 파일과 다른 파일에 연결되면 자동 쓰기를 중단합니다. Apps Script `FIT_SPREADSHEET_ID`를 사용하는 경우 실제 기록 파일과 일치시킵니다.

## 개발과 배포

```sh
npm ci
npm test
python3 tools/build-release.py
```

Playwright Chromium이 필요합니다. 설치된 실행 파일을 쓰려면 `CHROMIUM_PATH` 환경 변수로 지정할 수 있습니다. 백엔드·동기화 진단·두 기기 충돌·세트 입력/되돌리기/임시 저장·기구 도감·320–1200px UI·과거 기록 분리·PWA 갱신을 검증합니다.

프런트 파일 변경 후 서비스워커를 반드시 재생성합니다. `tools/build-release.py`가 25개 자산의 SHA-256을 묶어 릴리스를 생성합니다. 브랜치/PR만 업로드하면 운영 화면은 바뀌지 않습니다. main 병합 → Pages 배포 성공 → 앱의 업데이트 적용 순서입니다. 모든 자산이 같은 릴리스인지 검증한 뒤 오프라인 캐시에 넣으며, 입력 중 강제로 새 버전으로 전환하지 않습니다.

| 파일 | 역할 |
| --- | --- |
| `exercise-library.js`, `exercise-coaching.js`, `gym-inventory.js` | 올데이 기구·독립된 설명·도감 표시 |
| `training-plan.js` | 요일별 순서·세트·반복·적응 단계 |
| `record-model.js`, `reference-history.js` | 현재 운동 판별·이전 기록 조회 |
| `workout-log.js`, `workout-tools.js` | 세트·타이머·날짜별 계획·입력 복구 |
| `app-core.js`, `analytics.js`, `exercise-ui.js` | 공통 계산·분석·근육 지도 |
| `app.js`, `app-enhancements.js`, `interface-tools.js` | 초기화·인바디·화면·설정 |
| `storage.js`, `backup.js`, `sync-engine.js`, `session-schema.js` | 저장·백업·API 동기화·검증 |
| `index.html`, `styles.css`, `app-enhancements.css` | 페이지 구조와 반응형 디자인 |
| `pwa.js`, `sw.js`, `manifest.json`, 아이콘 | 설치·오프라인·업데이트 |
| `apps_script.gs` | Google Apps Script API v7 서버 |

원본 저장소 `ExLog.data`는 백업·동기화 전용으로 보존하고 추천·분석은 `ExLog.activeData`를 사용합니다. 저장소 마이그레이션과 구버전 백업 검증 코드는 기존 데이터 복구에 필요하므로 유지합니다.

## 동기화 차이가 계속 보일 때

관리 → 시트 연결 확인 → **다시 비교 · 읽기 전용**으로 현재 연결 파일을 다시 읽습니다. 인바디 숫자와 숫자 문자열, JSON 속성 순서, 내용 없는 당일 계획은 같은 값으로 비교합니다. 실제 중량·횟수·단위·메모·계획 변화는 계속 구분합니다. 읽기 실패 시 이전 차이 목록 대신 오류를 우선 표시하며, 최신 비교 전 덮어쓰기를 차단합니다.

문제가 남으면 **진단 내용 복사**로 앱·서버 버전, 연결된 파일, 기기/시트 날짜 수와 다른 항목을 확인할 수 있습니다. 연결키, 배포 URL, 세트별 값, 메모 본문은 복사하지 않습니다. 시트에 없는 기록을 삭제로 취급하거나 최초 연결의 서로 다른 기록을 자동 덮어쓰지 않습니다. 이번 프론트엔드 수정은 Apps Script 7.2.0과 호환됩니다.
