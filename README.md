# 운동 루틴 앱 — 운동별 기본 가중치와 자동 순서

GitHub Pages + Google Sheets 앱의 수정본입니다. 변경을 파일에 반영했으며 실제 GitHub 저장소와 Apps Script 배포에는 아직 반영하지 않았습니다.

## 적용 순서

1. 기존 앱 **관리 → 데이터 백업 → 내보내기 → 파일 저장**으로 전체 JSON 백업을 받습니다.
2. 연결된 Google Sheets의 Apps Script 편집기에 `apps_script.gs`를 반영합니다. **배포 → 배포 관리 → 기존 배포 편집 → 새 버전 → 배포**로 API v4를 적용합니다. 기존 배포를 편집하면 URL을 유지할 수 있습니다.
3. GitHub Pages의 기존 위치에 프런트 파일 7개를 함께 반영합니다: `index.html`, `exercise-library.js`, `training-plan.js`, **`app-enhancements.js`**, **`app-enhancements.css`**, `manifest.json`, `sw.js`. 굵게 표시한 JS·CSS는 새 필수 파일입니다.
4. 기존 `icon192.png`, `icon512.png`는 유지합니다. 첨부되지 않은 아이콘은 패키지에 포함하지 않았습니다.
5. 배포 완료 후 새로고침합니다. 이전 화면이 남으면 앱을 닫고 다시 실행합니다. 로컬 기록이 있으므로 사이트 저장소는 지우지 마세요.
6. 구름 버튼에서 **저장 & 동기화**를 실행합니다. 관리 탭에 설정 차이가 표시되면 비교 후 **이 기기 설정 사용** 또는 **시트 설정 불러오기**를 선택합니다.

Apps Script v4를 먼저 배포해야 일일 체중·설정 동기화가 작동합니다. 구버전 서버나 오프라인 환경에서도 편집 내용은 로컬에 보관합니다.

이전 수정본의 API v4를 이미 배포했다면 **이번 운동 가중치 수정으로 Apps Script를 다시 배포할 필요는 없습니다.** 프런트 파일을 함께 교체하면 됩니다.

## 운동별 순서 weight

가중치는 **도감의 운동 자체에 있는 기본 우선순위**입니다. 198종 모두 동작 특성, 주요 근육의 선행 피로, 현재 루틴의 상부 가슴·측면/후면 어깨 보완을 고려해 분류했습니다.

| 구간 | 범위 | 예시 | 분류 수 |
| --- | --- | --- | --- |
| 초반 | 100–199 | 데드리프트 120, 벤치프레스 130, 인클라인 머신·랫풀다운·V스쿼트 140 | 87 |
| 중반 | 200–299 | 래터럴 레이즈 210, 리어델트 220, 레그컬 230, 펙덱 235, 레그 익스텐션 240 | 56 |
| 후반 | 300–399 | 컬·푸시다운 300, 카프 320, 앱 휠 330, 플랭크 340, 데드행 350 | 55 |

숫자가 작을수록 앞에 배치합니다. 세부 숫자는 이 앱의 루틴 편성을 위한 판단값이며 연구에서 정한 점수는 아닙니다. 초반에는 주요 근력·기술 운동을, 중반에는 보조·고립 운동을, 후반에는 팔·코어·악력 등의 마무리를 둡니다. 측면·후면 어깨는 현재 보완 우선순위를 고려해 중반에 배치했습니다.

- **도감에서 추가 → 현재 선택한 운동일에 즉시 가중치 순으로 정렬**합니다. 마지막에 추가해도 가중치가 낮으면 앞으로 이동합니다.
- 운동 탭의 추가, 숨긴 운동 복구, 대체 운동 선택, 브랜드/기구 교체, 새로고침에 같은 기준을 적용합니다.
- **교체한 새 운동의 가중치**를 사용합니다. 교체 전 자리의 가중치를 이어받지 않습니다.
- 같은 운동은 어느 요일에서도 동일한 가중치입니다. 동률은 기본 루틴 순서, 추가 종목은 추가한 순서를 유지합니다.
- 운동 탭에 초반·중반·후반 구분선과 배지를, 도감에 가중치와 분류 이유를 표시합니다.
- **자동 순서·루틴** 화면에서 세트·반복을 편집할 수 있습니다. 순서 가중치는 도감 기본값을 읽어 표시합니다.
- 이전 수정본의 `plan_v2/plan_v3[요일].config[운동명].weight`는 수동 자리 번호였으므로 자동 정렬에서 무시합니다. 세트·반복·추가·삭제·교체 설정과 기존 데이터는 보존합니다.
- 도감에 없는 직접 입력 종목은 임의로 추정하지 않고 **미분류 400**으로 끝에 둡니다.
- 이는 **본세트의 기본 순서**입니다. 가벼운 밴드 외회전·데드버그·레그컬 등을 준비운동으로 사용할 때는 먼저 할 수 있습니다. 케틀벨 스윙은 파워 목적 본세트 기준으로 110을 부여했습니다.
- 같은 운동의 우선순위를 운동일마다 다르게 바꾸는 예외 설정은 넣지 않았습니다. 같은 종목의 고유 가중치가 일관되게 정렬 기준이 됩니다.
- 표시 순서 변경은 과거 운동 기록의 kg·세트·실제 수행 시각을 소급 변경하지 않습니다.

`exercise-library.js`의 종목 데이터 예시:

```js
{
  name: '바벨 벤치프레스',
  weight: 130,
  orderPhase: 'early',
  orderReason: '프리웨이트 복합운동의 자세와 수행 중량을 확보할 수 있도록 초반에 배치합니다.',
  // 기존 부위·설명·별칭 등은 유지
}
```

`EXERCISE_LIBRARY[].weight`는 순서용이고 실제 기록의 `sets[].weight`는 kg입니다. `training-plan.js`에는 요일별 종목과 세트·반복 처방을 보관하며 정렬용 자리 번호를 두지 않습니다. 가중치는 배포 파일을 통해 공유하므로 기기들이 같은 최신 파일을 사용해야 합니다.

분류 원칙 참고: [ACSM 2009 저항운동 진행 모델](https://pubmed.ncbi.nlm.nih.gov/19204579/), [ACSM 2026 저항운동 권고 개정](https://acsm.org/resistance-training-guidelines-update-2026/). 운동별 구체적인 숫자는 이 원칙과 현재 루틴 목적을 바탕으로 정한 앱 기본값입니다.

## 추가 기능

### 운동 집중 화면

한 운동의 지난 기록·오늘 세트·입력 버튼을 한 카드에 표시합니다. 이전/다음 버튼과 운동 선택 목록으로 이동하며 기존 세트 입력과 휴식 타이머를 사용합니다. **전체 운동 보기**로 전체 목록·요약을, **운동 설명 보기**로 설명·목표·세팅을 펼칩니다. 날짜 옆 루틴 배지를 누르면 운동일을 바꿀 수 있습니다. 수면·컨디션 입력은 유지합니다.

### 일일 체중과 7일 평균

**관리 → 일일 체중**에서 날짜별 입력·수정·삭제를 지원합니다. 같은 날짜는 한 건으로 갱신합니다. 오늘을 포함한 최근 7개 달력 날짜의 실제 입력값만 평균에 포함하고 빠진 날을 0이나 이전 값으로 채우지 않습니다. 기록 일수 `n/7`, 직전 7일 평균과의 차이, 유지 범위 83.5–84.5kg을 함께 표시합니다.

인바디와는 별도 기록입니다. 입력해도 인바디·골격근량 측정이나 과거 운동의 실부하를 다시 계산하지 않습니다. 최근 14개 기록을 수정·삭제할 수 있으며, 더 이전 날짜도 날짜 입력으로 갱신할 수 있습니다. 측정이 하루뿐이면 평균도 그 하루 값이므로 기록 일수를 함께 확인하세요.

### 주간 계획과 수행

**분석 → 이번 주 계획과 수행**에서 선택한 운동 기록 날짜가 속한 월–일 주간을 봅니다. 현재 편집한 종목별 세트와 복귀 일정으로 계획을 계산합니다. 10월 12–18일은 4회, 이후 기본 일정은 주 6회이며 12월 31일까지 집계합니다.

주간 전체 계획과 현재까지의 본세트를 비교합니다. 워밍업은 제외하고, 한 종목의 초과 수행이 다른 종목 부족분을 채우지 않게 합니다. 계획 외 종목은 따로 표시합니다. 과거 주간도 **현재 편집 루틴**으로 비교하며 과거 계획을 버전별로 재현하지는 않습니다. 기존 부위별 볼륨 카드의 기본 참고 목표와 달리 새 카드가 편집한 종목별 계획을 반영합니다.

### 기기 간 설정 동기화

같은 Apps Script URL을 사용하는 기기에서 루틴 구성·세트·반복, 선택한 프로필, 기구 기본 중량·부하 유형·환산 설정·메모·휴식·별칭, 훈련 블록·디로드를 공유합니다. 설정 변경은 자동 전송을 시도하며 **관리 → 기기 간 설정 → 설정 동기화**로도 확인합니다. 도감의 기본 가중치는 공통 코드에 포함됩니다.

서버 버전을 확인하고 저장합니다. 다른 기기에서 수정한 설정은 자동으로 덮어쓰지 않으며 항목별 요약과 실제 값 비교를 제공합니다. 처음 연결한 기기에 서버 설정이 이미 있으면 적용할 쪽을 선택합니다. 선택 도중 서버 버전이 다시 바뀌면 최신 차이를 다시 표시합니다. 선택한 쪽의 설정 전체를 적용하며 항목별 자동 병합은 하지 않습니다.

시트 설정을 불러오기 전 전체 JSON을 **복원 전 백업**에 보관합니다. 관리의 백업 영역에서 열 수 있으며 최신 스냅샷 한 개를 유지합니다. 배포 URL과 동기화 버전 정보는 설정 묶음에 전송하지 않습니다. 동기화 버전 정보는 기기별 정보이므로 휴대용 JSON 백업에서도 제외합니다.

## 데이터 보존과 제한

- 기존 운동·인바디 시트의 열을 이동하거나 삭제하지 않고 필요한 열만 추가합니다. 한글/영문 헤더와 이전 비고의 W·RPE·P를 읽습니다.
- 일일 체중은 `체중기록`, 설정은 `앱설정` 시트를 저장할 때 생성합니다. 확인만 할 때는 만들지 않습니다.
- 체중 삭제는 삭제 표시를 남겨 다른 기기로 전달합니다. 같은 날짜를 여러 기기에서 수정하면 서버에 나중에 저장한 값이 반영됩니다. 체중에는 설정과 같은 버전 충돌 화면이 없습니다.
- 미전송 체중은 시트 값으로 덮어쓰지 않습니다. 전송 중 다시 편집한 기록은 전송 대기에 남깁니다.
- 운동 기록의 기존 날짜별 미전송 보호, 삭제 재시도, 워밍업·RPE·통증·유산소·인바디 추가 항목을 유지합니다.
- 여러 기기에서 같은 운동 기록을 동시에 편집하는 자동 충돌 병합은 지원하지 않습니다. 설정 충돌 보호와 별개입니다.
- 수면·컨디션·세션 메모까지 다른 기기로 옮기려면 전체 JSON 백업을 사용합니다. 이 항목은 아직 시트 동기화 대상이 아닙니다.
- 설정 JSON이 시트 셀 저장 한도에 접근하면 전송을 거절하고 로컬 설정을 유지합니다.
- 서비스워커 v9는 운동별 가중치와 새 JS·CSS를 포함한 필수 파일을 캐시합니다.

## 검증

- 기존 1,210세트 보존 및 다섯 탭 렌더링
- 198종 가중치·구간·이유의 누락 검사, 기존 이름·별칭·설명 보존
- 도감의 실제 추가 버튼으로 후반→중반→초반 순서로 넣어도 자동 정렬
- 교체한 운동의 고유 가중치 적용, 요일 간 일관성, 동률 안정 정렬
- 이전 수동 가중치 무시 및 세트·반복 설정 보존, 숨김 복구·새로고침
- 집중 화면에서 실제 세트 입력 시 kg 보존
- 복귀 주간 계획, 워밍업 제외, 종목별 달성량 상한
- 누락·미래·삭제 체중을 제외한 7일 평균
- 설정 버전 충돌, 확인 중 재수정, 선택 적용과 복원 전 백업
- 전송 중 추가 편집한 체중의 대기 목록 유지
- 기존 시트 형식·사용자 추가 열 보존과 기록 왕복 동기화
- 모바일 320/390px 화면과 오프라인 재실행

Chromium과 메모리 기반 모의 Google Sheets API로 검증했습니다. 실제 사용자 Apps Script·GitHub Pages 배포 및 iOS Safari에서의 검증은 아직 수행하지 않았습니다. 운동 설명의 의학적 검토를 새로 수행한 버전은 아닙니다.
