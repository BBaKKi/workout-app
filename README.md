# 운동 노트 v7.4.0 — 화면 재설계·하단 휴식 타이머

## v7.4.0 변경 · 2026-10-18

- 운동·근육·도감·분석·관리 화면을 네이비·화이트·블루 공통 디자인으로 교체했습니다. 모바일은 하단 탐색, 넓은 화면은 왼쪽 탐색과 기록·코칭 2열 배치를 사용합니다.
- 휴식 타이머를 상단 전체 너비 막대에서 **하단 184px 타이머**로 변경했습니다. 탭해서 운동명·다음 세트·+30초·종료를 펼치고, Escape로 접을 수 있습니다. 모바일 하단 안전 영역을 반영하며 키보드로 화면이 줄어들 때 입력 영역을 비웁니다.
- 종료 시각 기반 계산, 백그라운드 알림과 재실행 복원을 유지합니다. 같은 운동을 새로 시작했을 때 이전 종료 예약이 새 타이머를 닫던 문제도 수정했습니다.
- 모든 운동 안내를 **핵심 요령 3개 / 시작 자세 / 한 번의 반복 / 자극과 근육의 역할 / 실수와 주의사항**으로 정리했습니다. 자세·팔꿈치 위치·기구 세팅·호흡·가동범위의 상세 설명을 보존합니다.
- 운동명에서 헬스장 표기를 작게 분리하고, 긴 중량 기록 기준·기구 목록 안내·배치 순서는 접어서 봅니다. 기록 식별에 쓰는 전체 운동명과 데이터 형식은 유지합니다.
- 사용하지 않는 상단 타이머 스타일과 중복 동기화 버튼을 제거했습니다. 동기화 연결은 운동 화면의 저장 상태와 관리 화면에서 열 수 있습니다.
- 320px에서 긴 운동명이 주간 보고를 밀어내는 문제를 수정했습니다. `tests/interface-v74.test.cjs`에 실제 세트 저장·타이머·화면 전환·가상 키보드 축소·기록 보존 회귀 검증을 추가했습니다. 키보드 검증은 브라우저의 visual viewport 시뮬레이션이며 실제 iPhone 확인은 별도입니다.

**적용 확인:** main 병합과 Pages 배포 후 앱의 **새 버전 준비됨 · 저장 후 업데이트**를 누르세요. 로고 옆(PC는 왼쪽 아래)의 **7.4.0**, 모바일 하단 메뉴, 도감 **현재 운동 59개**로 확인합니다. 브라우저 저장소를 지우거나 앱을 재설치할 필요는 없습니다. Apps Script는 기존 7.2.0/API 7을 그대로 사용합니다.

## v7.2.0 — 연결 진단·화면 재설계·운동 설명 확장

GitHub Pages + Google Sheets 개인 운동 앱 수정본입니다. 실제 GitHub 저장소나 Apps Script 배포는 변경하지 않았습니다. **이번에는 프런트 파일 전체와 Apps Script를 함께 업데이트해야 합니다.**

## 이번 변경

- **연결 진단:** 관리 → 시트 연결 확인 → 연결 진단에서 연결된 파일, 실제 탭 이름, 행 수, 유효 기록 날짜 수와 읽기 오류를 확인합니다. 진단은 읽기 전용이며 연결키는 표시하지 않습니다.
- **기록 보호:** 시트의 탭이나 날짜가 사라져도 로컬 기록을 자동 삭제하지 않습니다. 같은 배포 URL이 다른 파일을 가리키면 쓰기를 중단합니다. 필수 헤더 누락·중복 헤더·날짜 없는 기록은 빈 결과로 숨기지 않고 오류로 표시합니다.
- **탭 호환:** `운동기록`/`운동 기록`, `인바디기록`/`InBody`/`인바디`/`인바디 기록`을 인식합니다. 빈 기본 탭과 기록이 있는 별칭 탭이 함께 있으면 기록이 있는 탭을 사용합니다. 여러 후보에 기록이 있으면 임의로 합치지 않고 확인을 요청합니다.
- **화면:** 다섯 탭의 색상·글자·간격·입력 크기를 통일했습니다. 운동 화면은 세트 기록과 핵심 자세를 우선 표시하고, 자세한 수행 설명과 기구 설정은 펼쳐봅니다. 넓은 화면에서는 입력과 설명을 나란히 봅니다. 주간 리포트는 분석 탭에 모았습니다.
- **운동 설명:** 기존 도감 205개 항목(새 선택 199개 + 과거 표기 6개)과 올데이 초안 10개에 자세한 안내를 표시합니다. 52개 동작 유형에 종목별 변형과 기존 기구 설명을 결합해 팔꿈치·몸통·골반·발 위치, 근육 작용, 반복 순서, 실수와 교정, 주의 신호를 설명합니다. 기구의 현장 모델을 모두 확인했다는 의미는 아닙니다.
- **비교 화면:** 차이 건수는 중복행 수가 아닌 날짜·종류별 불일치 수입니다. 8개씩 펼쳐볼 수 있고, 인바디·당일 계획은 사람이 읽을 수 있는 항목으로 비교합니다.
- **정리:** 사용 경로가 없던 워밍업 자동 계산·주입 코드, 중복 정렬/처방 덮어쓰기, 이전 설명 렌더러와 관련 스타일을 제거했습니다. 기록된 워밍업 세트와 기존 설정 이전·복구 코드는 유지합니다. 기본 중량/휴식 설정 패널의 충돌도 수정했습니다.
- v7.1.1의 일부 세트ID 이관 충돌 수정은 유지합니다. 실제로 저장된 같은 ID가 있으면 행 번호를 안내하며 기록 내용을 임의로 삭제하지 않습니다.

## 먼저 적용하기

1. 기존 앱에서 JSON 백업을 받고 시트 사본을 만듭니다. 브라우저 저장소를 지우지 않습니다.
2. Apps Script를 `apps_script.gs`로 교체하고 **기존 웹 앱 배포 편집 → 새 버전 → 배포**합니다. `FIT_API_TOKEN`과 기존 `/exec` URL은 유지합니다.
3. 아래 표의 프런트 파일 **25개**를 함께 교체합니다. 새 `exercise-coaching.js`, `icon192.png`, `icon512.png`도 포함합니다.
4. Pages 배포 후 기존 앱 창을 모두 닫고 다시 엽니다. `/exec`의 `serverBuild`는 `7.2.0`, 앱 상단은 `7.2`여야 합니다.
5. **관리 → 시트 연결 확인 → 연결 진단**을 실행합니다. 시트 링크가 실제 기록 파일인지 먼저 확인합니다.

### 42건 모두 시트에 없다고 나오는 경우

현재 실제 배포·시트에 접근해 원인을 확정한 것은 아닙니다. 아래 결과로 구분할 수 있도록 코드를 보완했습니다.

| 진단 결과 | 확인할 사항 |
| --- | --- |
| 파일 이름/링크가 다름 | 기록 파일에서 연 Apps Script인지 확인합니다. 필요하면 스크립트 속성 `FIT_SPREADSHEET_ID`에 실제 스프레드시트 ID를 지정합니다. URL 전체가 아니라 `/d/` 다음의 ID입니다. 연결키와는 별개입니다. |
| 해당 탭 없음 | 진단의 전체 탭 목록과 지원 이름을 비교합니다. 특히 과거 `InBody` 탭은 이번 버전부터 직접 읽습니다. |
| 필수 열 오류 | 오류에 나온 탭의 첫 행을 확인합니다. 지원되는 한글 또는 영문 헤더가 필요합니다. 기록 행을 지워 해결하지 않습니다. |
| 읽을 탭이 여러 개 | 같은 종류의 탭 여러 개에 기록이 있습니다. 실제 사용할 탭과 각 기록을 확인한 뒤 정리해야 합니다. 앱은 합치거나 덮어쓰지 않습니다. |
| 올바른 파일에서 실제로 빈 기록 | 로컬 백업을 유지하고 날짜별 비교에서 **이 기기 기록을 시트에 저장**을 선택합니다. 빈 시트를 로컬 삭제로 적용하는 버튼은 비활성화됩니다. |

한번 동기화한 배포 URL의 연결 파일 ID가 변경되면 쓰기를 막습니다. 의도한 새 파일 이관은 이 버전에서 자동 처리하지 않으므로 기존 기록 파일로 연결을 복구하세요. `FIT_SPREADSHEET_ID`를 지정하지 않으면 기존처럼 연결된 스프레드시트를 사용합니다.

- 종류가 불분명하거나 한 운동으로 정의할 수 없는 3개 항목은 접이식 안내에만 둡니다. 상세 근거는 `GYM_INVENTORY.md`를 참고하세요.

- 기구의 정확한 모델과 중량 표기는 방문 후 기구 세팅에 기록하세요. 현재는 같은 이름 아래 여러 기구를 나누는 짐 프로필 기능까지 구현한 것은 아닙니다. 동일 종목을 새 짐에서 구분하려면 반드시 초안의 전용 항목을 선택해야 합니다.

## 적용 순서

1. 기존 앱의 **관리 → 데이터 백업 → 내보내기 → 파일 저장**으로 JSON 백업을 받고, Google Sheets도 사본을 만듭니다. 모든 기기의 앱을 닫습니다.
2. Google Sheets에 연결된 Apps Script에서 기존 서버 코드를 `apps_script.gs` 내용으로 교체합니다. 파일명은 `Code.gs`여도 됩니다. 기존 `doGet` / `doPost`는 중복해서 남기지 않습니다.
3. Apps Script **프로젝트 설정 → 스크립트 속성**에 `FIT_API_TOKEN`을 추가합니다. 기존 버전에서 설정한 연결키가 있으면 그대로 사용합니다. 새로 설정하는 값은 비밀번호 생성기 등으로 만든 **32자 이상의 충분히 긴 무작위 연결키**를 사용합니다. GitHub 파일이나 배포 URL에 넣지 마세요.
4. **배포 → 배포 관리 → 기존 배포 편집 → 새 버전 → 배포**로 API v7을 배포합니다. 기존 배포를 편집하면 `/exec` URL을 유지할 수 있습니다. 기존의 실행 주체·접근 설정을 확인하세요. 이 앱은 연결키를 가진 개인 기기에서 호출하는 방식입니다.
5. GitHub Pages 폴더에 아래 **프런트 파일 25개를 한 커밋으로 함께 교체·추가**합니다. 아이콘 파일도 ZIP에 포함되어 있습니다.
6. Pages 배포가 끝나면 모든 기존 앱 탭·설치형 앱 창을 닫고 다시 엽니다. **사이트 데이터나 브라우저 저장소는 지우지 마세요.**
7. 앱의 구름 버튼에서 기존 `/exec` URL과 3번의 연결키를 입력하고 **연결 저장 & 동기화**를 누릅니다. 각 기기에 연결키를 한 번씩 입력합니다.
8. 관리 탭에 기록 차이가 표시되면 날짜별 양쪽 값을 확인하고 적용할 쪽을 선택합니다. 처음 연결할 때 서버에 없는 로컬 과거 기록도 확인 대상으로 표시합니다. 같은 기록은 자동으로 일치 처리합니다.

**v6 이하에서 업데이트할 때는 Apps Script도 반드시 API v7으로 다시 배포해야 합니다.** API v6 이하 앱과 함께 사용하지 마세요. v7 서버는 연결키 없는 요청과 구버전의 `upsert/delete/pull/export` 요청을 거부합니다. 남아 있는 구버전 기기가 기록을 덮어쓰지 않도록 모든 기기를 업데이트하세요.

### 바로잡은 오류

- 과거 어시스트 운동을 불러올 때 **기록 당시 날짜의 체중**을 사용합니다. 그때까지 체중 기록이 없으면 미래 체중을 가져오지 않습니다. 이미 저장된 당시 부하 정보는 유지합니다.
- 주간 계획 달성률은 **날짜와 운동이 일치하는 계획·실적**으로 계산합니다. 당시 계획이 없는 과거 실적은 별도로 표시하고 달성률 분자에도 넣지 않습니다.
- 컨디션·메모·당일 계획만 바뀌어도 동기화 전송 대기 건수에 표시합니다.
- 앱은 기본적으로 오늘 날짜를 엽니다. 과거 날짜의 미완성 입력이 있을 때만 이어가기 선택을 제공합니다.
- 주간 운동일 목표를 고정 6일에서 해당 주 계획 기준으로 바꿨습니다. 복귀 첫 주는 4일로 표시됩니다.

### 기존 기록과 v7 데이터 형식

- 서로 다른 이름을 연결해 보던 기록은 이제 원래 이름별로 나뉩니다. 따라서 합쳐 보이던 PR·그래프가 달라질 수 있지만 기존 세트는 보존됩니다. 도감의 검색용 동의어는 설명을 찾는 데만 사용합니다.
- 원래 운동명을 기준으로 고유 식별자를 부여합니다. 이번 버전에 운동명 변경 화면은 추가하지 않았습니다.
- 과거 파머스 워크처럼 단위가 선언되지 않은 기록을 임의로 거리로 해석하지 않습니다. 새 기록부터 명시적인 단위를 저장합니다.
- 기존 운동기록 열은 유지하고 **기록정보JSON** 열에 운동 식별자·단위·당시 부하·유산소 거리/경사를 추가 저장합니다. 기존 **운동세션** 시트에는 날짜별 계획·교체와 컨디션·수면·메모를 함께 저장합니다.
- 운동 세트와 날짜별 세션 정보는 별도 충돌 항목입니다. 같은 날짜에서 두 항목 모두 차이가 나면 각각 확인합니다.
- 첫 세트 또는 당일 계획 변경 시 당시 종목·순서·세트·반복 목표를 보관합니다. 도입 전 날짜의 목표를 현재 루틴으로 채우지 않습니다. 과거 날짜에 새로 입력한 계획은 **사후 입력 계획**으로 구분합니다.
- **앞으로도 적용**은 해당 날짜와 기본 루틴을 함께 바꿉니다. 다른 날짜에서 이미 보관한 계획에는 소급하지 않습니다.
- 세트 되돌리기·입력 임시 저장·휴식 복구·기구 세팅·동기화 활동 기록 등 이전 버전의 기능은 유지합니다. 미확정 입력과 되돌리기 기록은 기기별입니다.

### 운동 설명 정리

기존 **198개 항목의 설명을 모두 검토·수정**했습니다. 새 선택 목록은 **199개**입니다. 중복·혼합·오표기 6개는 새 선택에서 제외하고 과거 기록 조회용으로 유지했으며, 서로 다른 도구·모드를 7개의 명확한 항목으로 나눴습니다.

- 케이블 풀오버의 기존 설명은 스트레이트암 풀다운과 중복되어 새 선택에서 통합했습니다.
- 케이블/컨센트레이션 컬, Hammer Chest/Back, Booty Builder 멀티 하체 기구는 동작별로 분리했습니다.
- 90도 인클라인 리어 델트 표기와 Booty Builder 스탠딩 어덕션/어브덕션 혼동을 정리했습니다.
- 서로 다른 브랜드·모델은 유지합니다. 모델 확인이 필요한 항목에는 확인 안내를 넣었습니다. 과거 기록 이름·세트·중량은 일괄 변경하지 않습니다.
- 과도한 효과 단정, 통증 원인 진단, 고정된 개인 증량 목표를 제거하고 실제 세팅·편안한 가동범위·통제 방법을 안내합니다.
- 도감·운동 카드·근육 설명의 중복·상충 문구를 정리했습니다. 일반 호흡·기록 기준은 도감의 공통 안내에서 확인할 수 있습니다.

자세한 항목별 결과와 근거는 **EXERCISE_REVIEW.md**에 있습니다. 파머스 워크 설명은 이번 거리(m) 입력에 맞춰 갱신했습니다.

## 기존 기록 보호 기능

### 최신 기록과 삭제 보호

- 일반·수동 동기화 모두 **시트를 먼저 확인하고 실제 변경분만 전송**합니다. 일요일의 자동 전체 업로드를 제거했습니다.
- 운동·체중·인바디·당일 계획에 날짜별 버전 비교를 적용했습니다. 같은 날짜를 양쪽에서 수정하면 자동으로 덮어쓰지 않습니다.
- 서버 버전은 앱이 관리하는 시트 값의 해시입니다. 해당 셀을 직접 수정한 경우도 다음 동기화에서 변경으로 인식합니다. 시트 직접 편집과 앱 전송을 같은 순간에 실행하는 것은 피하세요. Apps Script 잠금은 다른 Apps Script 요청끼리 적용됩니다.
- 비교 화면을 보는 도중 서버나 로컬이 다시 바뀌면 최신 내용을 다시 확인합니다. 선택 전에는 현재 앱의 JSON 복원 전 백업을 저장합니다.
- 세트는 고유 `세트ID`로 구분합니다. 중간 세트를 삭제해 번호가 당겨져도 다른 세트로 혼동하지 않습니다.
- 삭제한 운동 세트는 시트의 **삭제** 열에 `TRUE`를 남깁니다. 마지막 세트를 삭제한 날짜도 다른 기기에 전달됩니다. 앱은 삭제된 행을 운동량 계산에서 제외합니다.
- 기존 시트의 세트 번호가 중복되어도 행을 버리지 않습니다. 날짜·종목별 시트 행 순서를 유지하면서 번호와 ID를 정리합니다. 기존 행은 최초 v5 쓰기 때 일괄 이관됩니다.
- 시트에서 직접 합계·차트를 만들었다면 **삭제 열이 TRUE인 행을 제외**하도록 필터/수식을 조정하세요. 기존 사용자 수식은 자동으로 변경하지 않습니다.
- 시트에 없는 로컬 과거 기록을 처음 연결한 기기가 자동 업로드하지 않습니다. 관리 탭에서 해당 날짜를 확인한 뒤 업로드할 수 있습니다.
- 네트워크 응답을 잃은 뒤 같은 요청을 재전송해도, 이미 저장된 동일한 내용이면 정상 완료로 처리합니다.
- 설정은 기존의 버전 비교를 유지하며, 시트 설정을 적용할 때도 검증과 되돌리기 가능한 교체를 사용합니다.

### 로컬 저장과 백업

- 저장 공간 부족 등 오류가 나면 오류 배너를 표시하고 미저장 입력이 있다는 것을 알립니다.
- **저장 재시도**, **현재 입력 파일 백업**을 제공합니다. 긴급 백업은 저장소 쓰기가 실패해도 메모리의 운동·체중·인바디·루틴 입력을 파일로 만들 수 있습니다.
- 백업 내부의 월별 JSON, 날짜, 세트, 숫자 범위, 루틴 구성을 먼저 검증합니다. 검증 실패 시 기존 기록을 건드리지 않습니다.
- 가져오기 전 현재 데이터를 복원 전 백업으로 보관합니다. 여러 키를 교체할 때는 되돌리기 정보를 먼저 저장합니다. 중간 실패 시 원래 저장값으로 복구하고, 실행이 중단됐다면 다음 시작에서 복구합니다.
- 가져온 백업의 서버 기준 버전은 새 기기에서 재사용하지 않습니다. 복원 후 시트와 다시 비교합니다.
- 다른 탭이 같은 기기의 기록을 바꾸면 오래된 메모리 내용으로 덮어쓰지 않도록 새로고침을 안내합니다. 미저장 입력이 있으면 먼저 긴급 백업을 받으세요.
- 연결키와 기기별 서버 버전은 휴대용 JSON 백업에 포함하지 않습니다.

### 연결키

- 연결키가 설정되지 않은 서버는 기록 조회·수정을 허용하지 않습니다.
- `GET`은 서버 동작 여부·API 버전만 반환합니다. 운동·체중·설정 조회도 연결키가 있는 `POST`를 사용합니다.
- 연결키는 Apps Script의 스크립트 속성과 각 기기의 브라우저 저장소에만 둡니다. 연결키를 가진 사람은 기록을 읽고 수정할 수 있으므로 비밀번호처럼 관리하세요.
- 연결키를 변경하려면 스크립트 속성 값을 교체한 뒤 각 기기의 앱에서 새 값을 입력합니다. 스크립트 속성 값 변경만으로 코드를 다시 배포할 필요는 없습니다.
- 이 방식은 개인용 공통 연결키 인증입니다. 사용자별 계정·역할·접근 로그를 제공하는 다중 사용자 서비스 인증은 아닙니다.

### 성능과 코드 구조

- 시트 행을 메모리에서 인덱싱하고, 연속된 앱 관리 열을 묶어서 씁니다. 세트 하나마다 시트 전체를 검색하고 한 번씩 쓰던 처리를 줄였습니다.
- 사용자 추가 열은 읽은 계산값으로 다시 덮어쓰지 않습니다. 추가 열의 수식·메모 값을 보존합니다.
- HTML에 들어 있던 큰 스크립트와 스타일을 분리했습니다. 특히 저장·백업·동기화·캐시 갱신은 별도 파일에서 관리합니다.
- 기록은 `workout-log.js`, 분석은 `analytics.js`, 도감은 `exercise-ui.js`에서 관리합니다. 기존 프레임워크 없는 JavaScript 구조는 유지합니다.

### 화면과 계획

- 도감의 운동별 고유 `weight`를 그대로 유지합니다. 낮은 값부터 자동 정렬하고, 같은 값은 기존 순서를 유지합니다. 실제 중량 `sets[].weight`와 별개입니다.
- 운동일의 상단 설명을 **실제로 정렬된 첫 두 운동**에 맞춰 표시합니다.
- 관리 탭에서 시작일·종료일·체중 유지 범위를 수정할 수 있습니다. 시작일은 요일 표시와 복귀 일정을 맞추기 위해 월요일로 제한합니다.
- 기본값은 2026-10-12~2026-12-31, 83.5~84.5kg입니다. 처음 1주는 4회·2세트, 2주는 적응 단계, 이후 기본 루틴이며 종료 직전에는 점검 단계로 표시합니다.
- 체성분 목표는 기존 참고값을 유지합니다. 기간이나 목표 체중을 바꿨다고 새로운 체성분 도달 가능성을 예측하지 않습니다.

### 오프라인과 배포 일관성

- 새 서비스워커는 프런트 파일 24개의 SHA-256 해시를 확인한 후 하나의 버전으로 캐시합니다.
- 배포 파일이 일부만 바뀌었거나 누락되면 새 버전 설치를 거부하고 기존 캐시를 유지합니다.
- 새 버전은 **저장 후 업데이트** 버튼을 누르거나 기존 창을 모두 닫을 때 적용합니다. 입력 중인 세트가 있으면 확정·취소 후 업데이트하도록 안내합니다.
- 이후 프런트 파일을 수정했다면 배포 전에 반드시 `python3 tools/build-release.py`를 실행해 `sw.js`를 다시 생성하고, 전체 프런트 파일을 한 커밋으로 올리세요. 해시가 다르면 업데이트가 설치되지 않습니다.

## 검증

포함된 `tests/`는 합성 데이터만 사용하며 실제 개인 운동 기록·연결키를 포함하지 않습니다.

```sh
npm install
npx playwright install chromium
npm run release
npm test
```

이미 Chromium이 설치된 환경에서는 `CHROMIUM_PATH=/absolute/path/to/chromium npm test`로 지정할 수 있습니다. 서버 테스트는 메모리 기반 Google Sheets 모의 객체를 사용합니다.

검증한 항목:

- v7.2: 탭 별칭·모호한 탭·필수/중복 헤더·날짜 누락, 잘못된 연결 파일, 인증 전 접근 차단, 읽기 전용 진단, 스프레드시트 시간대, 원격 탭 누락 시 로컬 보존, 빈 시트 삭제 적용 차단, 42건 페이지 표시를 합성 데이터로 검증했습니다.
- 215개 설명 표시와 변형별 안내, 기구 설정 상호작용, 다섯 화면의 320/390/768/1200px 가로 넘침, 기존 기록/루틴/백업/오프라인 회귀 검증을 포함합니다.

- v7.1.1: ID가 일부만 저장된 시트의 양쪽 행 순서, 삭제된 ID 예약, 반복 읽기의 안정성, 실제 저장된 ID 충돌의 행 번호 안내, 사용자 수식 보존, 오래된 버전의 쓰기 충돌 보호. 제공된 원본 1,210건과 6월 29일 24세트의 조회·ID 이관·쓰기 후 재조회는 로컬 모의 시트에서 검증했습니다. 현재 사용 중인 실제 시트의 충돌 원인은 직접 확인하지 않았습니다.

- 올데이 기구 초안: 기구 10개와 안내 3건, 출처·상태·한글 검색·브랜드 필터, 320px 모바일 넘침 없음, 당일 추가, 기존 기구 이력·세팅 분리, API v7 동기화·백업 검증·재시작 후 복원. 기존 일반 도감 199종과 보존 표기 6종은 유지합니다.

- 기존 운동 연결의 제거, 연결된 메모·휴식·기본 중량 이전, 재시작 후 독립 기록 유지
- 당일 추가·건너뛰기·복구와 영구 루틴 변경의 적용 범위, 기존 세트 보존
- 두 기기 사이 수면·컨디션·메모 변경/비우기와 거리·경사 왕복 저장
- 반복 칩 선택 후 명시적인 세트 확정, 즐겨찾기 동기화·백업, 카드 메뉴 중복 방지
- 과거 체중 계산, 세션만 변경했을 때 대기 표시, 날짜별 주간 실적 매칭, 복귀 주 목표
- 오늘 날짜 시작과 과거 미완성 입력의 선택적 이어가기

- 날짜별 교체 후 재시작·다른 기기 복구와 계획 충돌 처리
- 입력 임시 저장·운동 위치·휴식 복구, 수정·삭제 되돌리기
- 특이 입력의 취소·강제 저장, 기구 세팅의 동기화·백업
- 199개 활성 항목·6개 과거 항목 보존과 단일 설명 적용

- 인증 없는 조회/수정 및 구버전 쓰기 차단
- 기존 한글/영문 시트와 워밍업·RPE·통증 읽기
- 두 기기의 운동·체중 충돌과 사용자의 선택 적용
- 오래된 전체 전송 플래그가 최신 값을 덮어쓰지 않음
- 마지막 세트 삭제 전달·재전송과 중간 세트 삭제 시 ID 보존
- 전송 중 다시 편집한 기록의 대기 상태 보존
- 잘못된 백업 거부, 저장 공간 부족 시 오류와 교체 되돌리기
- 사용자 추가 수식 보존과 1,000세트 일괄 쓰기
- 실제 도감 추가 경로의 가중치 정렬·320px 화면
- 완전한 캐시의 오프라인 실행, 섞인 버전 거부와 업데이트 적용

별도로 제공된 과거 기록 **1,210건(웨이트 1,209세트 + 유산소 1건)**을 넣어 이관·조회, 불필요한 초기 동기화 충돌이 없음, 다섯 탭, 실제 집중 화면 입력과 새로고침 후 보존을 확인했습니다. 이 개인 데이터는 테스트 패키지에 넣지 않았습니다.

실제 사용자 Apps Script·GitHub Pages 배포 및 iOS Safari 실기기 검증은 수행하지 않았습니다. Google Sheets 쓰기는 데이터베이스 트랜잭션이 아니므로 서비스 오류로 일부 열 쓰기만 끝난 경우 로컬 대기 기록을 유지하고 다음 동기화에서 차이를 확인합니다.
