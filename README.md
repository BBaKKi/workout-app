# 운동 노트 v7.6.7 — 수행 포인트와 기록 조건별 비교


[운동 앱 열기](https://bbakki.github.io/workout-app/)

## 이번 변경

- **87개 운동**에서 높이·몸 위치, 그립, 유지할 자세, 이동 경로, 힘·자극 방향, 자세 교정을 한 번씩만 보여줍니다. 중복되던 세팅·당기는 구간 설명을 제거하고 **복귀·다음 반복 / 놓치기 쉬운 2가지**를 추가했습니다.
- 레그컬의 골반 밀림·롤러 이동, 프레스의 전완 정렬·패드 접촉, 래터럴의 팔꿈치 각도 변화, 힌지의 무릎 이동처럼 직접 관찰할 변화와 조정 방법을 연결합니다. 설치 모델이 확인되지 않은 기구의 조절 장치는 조건부로 설명합니다.
- 분석의 **종목별 직전 수행 비교**는 세트별 중량·체중/보조 조건·단위·세트 수가 같을 때만 총반복 변화를 표시합니다. 마지막 RPE를 함께 보여주며, 조건이 바뀌거나 21일 넘게 공백이 있으면 별도 상태로 안내합니다. 자세·가동범위가 같다는 뜻은 아닙니다.
- 서로 다른 세트 구성을 최고 추정 1RM 하나로 비교해 정체·종목 교체를 권하던 안내를 제거했습니다. 실제 두 날짜의 세트를 펼쳐 확인할 수 있고 기존 중량 추천 규칙과 루틴은 유지합니다.
- 체성분은 마지막 측정 기준 최근 28일의 **실제 비교 날짜·횟수·체지방량(체중×체지방률)**을 함께 표시합니다. 체지방률만 떨어지고 계산 지방량은 거의 같은 경우를 구분하고, 짧은 기간의 골격근량 변화로 식사 부족이나 근육 증감을 단정하지 않습니다.
- 운동명·ID·분류, 목표, 저장 기록, 기기 보관 정책과 시트 API는 그대로입니다. 설명을 읽거나 추세를 보는 동작은 기록·계획을 수정하지 않습니다.

**업데이트:** 프론트엔드 배포 후 앱의 **새 버전 준비됨 · 저장 후 업데이트**를 누르고 로고 옆 **7.6.7**을 확인하세요. 연결 진단이 이미 **Apps Script 7.3.0**이면 이번에는 스크립트 변경·재배포가 필요하지 않습니다. 아직 7.2.x라면 아래 이전 버전 배포 절차를 먼저 따르세요.

## v7.6.6에서 이어지는 최근 기록 보관

- 운동·지난 당일 계획·매일 체중은 **최근 30일**, 인바디는 **최근 8회**를 기기에 보관합니다. 현재 루틴·기구 세팅·미래 계획은 유지합니다.
- **서버에서 동일한 기록과 버전을 확인한 경우에만** 오래된 기기 사본을 비웁니다. 미전송·충돌·시트 누락·임시 입력·현재 열람 중인 운동일은 추가로 유지합니다. 기기 캐시 정리는 시트 삭제 요청을 생성하지 않습니다.
- 날짜 범위를 명시한 `sync_window` API를 추가했습니다. 인바디 최근 8회와 기기에 남은 과거 기록의 확인 범위를 응답에 명시합니다. 추가 확인은 요청당 종류별 최대 500일로 나누며 새 기기는 과거 전체 세트를 내려받지 않습니다.
- 이전 최고 기록·종목별 마지막 수행·중량 증분·순환 순서·누적 운동 횟수·8주 볼륨은 작은 요약값으로 유지합니다. 인바디 최초 측정값은 목표 진행률의 기준 요약으로 유지합니다.
- 관리 → **이전 기록 · 시트에서 조회**에서 최대 31일 범위를 읽기 전용으로 조회합니다. 조회 결과는 로컬 기록에 합치지 않고 화면을 닫으면 메모리에서도 비웁니다. 이전 날짜/주/종목 이력에서도 이 화면으로 이동할 수 있습니다.
- 내보내기는 **이 기기의 최근 기록·미전송 기록·설정** 백업입니다. 전체 상세 이력은 Google Sheets에 있습니다. 기존 복원용 안전 백업은 유지하고 새로 만드는 백업은 현재 기기 범위를 따릅니다.

### v7.6.6 보관 정책을 처음 적용할 때의 배포 순서

1. 저장 오류가 있다면 **현재 입력 파일 백업**을 먼저 파일로 보관합니다.
2. [apps_script.gs](apps_script.gs)를 기존 Apps Script 프로젝트에 반영합니다. **배포 관리 → 기존 웹 앱 편집 → 새 버전**으로 배포하면 `/exec` URL과 기존 토큰·시트 설정을 유지할 수 있습니다. 서버 빌드는 **7.3.0**입니다. 기존 앱의 `sync_pull`도 계속 지원합니다.
3. 프론트엔드 배포 후 **7.6.6**으로 업데이트하고 시트를 동기화합니다. 시트 저장 확인 후부터 최근 기록 보관 정책이 적용됩니다. 서버 업데이트 전에는 정리하지 않고 안내 메시지를 표시합니다.
4. 관리의 **저장 공간 확인**, **이전 기록 · 시트에서 조회**에서 보관 상태와 과거 기록을 확인합니다. 사이트 데이터 삭제나 앱 재설치는 필요하지 않습니다.

기기의 보관 개수가 30일/8회를 초과하는 경우에는 미전송·충돌·확인 전 기록 또는 현재 열람 중인 기록을 먼저 확인하세요. 시트가 없거나 연결이 실패한 상태에서 나이를 기준으로 기록을 삭제하지 않습니다. 오프라인에서는 기기에 보관된 범위만 볼 수 있습니다.

### v7.6.5에서 이어지는 저장 공간 복구

- 동기화 비교용 사본을 SHA-256 요약으로 저장합니다. 실제 운동·인바디·체중·당일 계획과 전송 대기열은 유지합니다. 기존 비교 형식의 정규화, setId·시각·볼륨을 포함한 누락 응답 확인도 유지합니다.
- 새 비교 정보는 `record_sync_v6`에 저장합니다. `record_sync_v5`는 새 값을 저장한 뒤에만 제거하여 구버전 탭이 요약값을 기존 원문으로 해석하지 않도록 합니다.
- 복원 전 백업은 IndexedDB에 저장하며 기존 localStorage 백업은 **공간 복구 후 저장 재시도**에서 옮깁니다. 쓰기 완료와 동일한 내용의 재조회가 성공한 뒤에만 기존 사본을 제거합니다. **복원 전 백업 열기**는 계속 사용할 수 있습니다.
- 여러 항목을 저장할 때 바뀐 항목만 임시 복사합니다. 단일 항목은 브라우저의 원자적 저장을 사용하며 여러 항목 변경의 실패 복구는 유지합니다.
- 오류 화면에서 미저장 입력 백업과 공간 복구를 제공하고, 백업 메뉴의 **저장 공간 확인**에 기록·비교 정보·복원 사본 등의 추정 크기를 표시합니다. 사진·사이트 데이터나 실제 운동 기록을 자동 삭제하지 않습니다.

**오류가 이미 발생했다면:** 먼저 **현재 입력 파일 백업**으로 JSON 파일을 저장하세요. 업데이트 후 로고 옆 **7.6.7**을 확인하고 필요하면 **공간 복구 후 저장 재시도**를 누르세요. 구버전에서 저장 오류 때문에 업데이트 버튼이 막힌 경우, 백업이 실제로 저장되었는지 확인한 뒤 새 버전 설치를 기다리고 운동 앱과 같은 사이트를 연 Safari 탭을 모두 닫았다 다시 여세요. 사라진 미저장 입력은 받은 파일로 복원합니다. 웹사이트 데이터 삭제나 앱 재설치는 필요하지 않습니다.

저장 한도 자체를 없애는 변경은 아닙니다. 실제 기록만으로 한도에 도달하거나 별도 백업 저장소도 사용할 수 없으면 오류를 유지하고 원본을 보존합니다. 사용량 수치는 문자열 기준 추정치이며 기기 전체 용량을 나타내지 않습니다.

### v7.6.3에서 이어지는 구성

- 11월 2일 이후 올데이 기본 편성: Legs A의 마지막은 고관절 외전 2×15–20, Push B의 삼두는 Paramount 2×10–15, Pull B의 이두는 Cybex 암컬 2×10–15입니다. Legs B에는 크런치를 유지합니다. 기본 합계는 6세션 65본세트이며 저장된 당일 계획은 우선합니다.

- 사용자 보유 확인으로 Cybex 트라이셉스 암 익스텐션을 추가했습니다. 도감의 푸시·소근육에서 ‘암 익스텐션 머신’을 검색하면 Paramount와 Cybex 두 기구가 나옵니다. 두 기구의 기록과 이두 암컬의 기록은 각각 유지합니다. Cybex 삼두 머신은 도감에서 선택하는 대안입니다.
- 수행 설명 참고: [Cybex VR3 Arm Extension 설명서 14쪽](https://kb.cybexintl.com/Owners_Manuals/Strength/12080-999-4.pdf#page=14). 올데이 기구의 세부 모델은 확인되지 않았습니다.

### v7.6.2에서 이어지는 구성

- 첫 세트는 입력 패널의 루틴을 당일 분류에 먼저 반영한 뒤 계획과 함께 저장합니다. 재개 화면과 세션 기본값이 달라도 같은 분류로 저장됩니다.
- 기록을 시작한 뒤 상단 루틴 탭은 다른 루틴을 살펴보는 용도로 사용합니다. 날짜 전체 분류는 날짜 옆 루틴 버튼에서 명시적으로 변경하고 확인합니다. 다른 분류의 패널에서 세트를 저장하면 입력을 보관하고 분류 선택을 안내합니다.
- 재개 시 이미 기록한 날짜의 분류를 우선하고, 시트 동기화로 분류가 바뀌면 날짜 배지와 패널도 함께 갱신합니다. 기존 기록을 운동명으로 추정해 자동 변경하지 않습니다.
- 시트를 직접 수정하면 기존 API v7의 날짜별 내용 해시가 바뀝니다. 변경 없는 기기는 시트 값을 받아오며, 미전송 변경이 있는 기기는 충돌 선택을 유지합니다. 충돌 날짜는 기기 JSON 백업 후 세트 수·ID·중량·횟수·RPE·시각을 비교하고 선택하세요. 실제 배포된 Apps Script 버전은 연결 진단으로 별도 확인할 수 있습니다.

### v7.6.1에서 이어지는 구성

- 준비운동은 기록하지 않습니다. 신규 워밍업 토글·임시입력·전용 휴식 분기를 제거하고, 이전 기록을 수정할 때 워밍업 표시가 지워지던 오류는 고쳤습니다.
- 휴대폰·태블릿의 모든 입력/선택/텍스트 영역은 최소 16px로 표시합니다. 페이지 전체에 `touch-action: manipulation`을 적용해 연속 탭 확대를 억제하며 스크롤·의도적인 핀치 확대는 유지합니다. iPhone 실기기의 키보드/자동 확대는 별도 확인이 필요합니다.
- 진행률과 완료 알림은 종목마다 한 세트가 아니라 저장된 목표 본세트 수를 기준으로 계산합니다.
- 자동 증량은 14일 이내 두 세션의 같은 중량·반복 상한과 마지막 본세트 RPE ≤8을 확인합니다. 다른 세트에 입력된 RPE >8도 보류 사유로 반영합니다. RPE는 선택 입력이며 없을 때는 기록 실패가 아닌 자동 판단 보류로 안내합니다.
- 67개 수행 가이드를 검토하고 18개에서 견갑골 움직임과 몸통 지지, RDL 종료 자세, 래터럴 복귀 표현을 보완했습니다. 기존 종목·ID·편성량·목표는 유지합니다.
- 작은 화면의 시작 영역을 줄이고, 순서 배지를 실제 수행 순번으로 표시합니다. 중복 지난 기록을 제거하고 저장한 기구 세팅을 기록 영역에 표시합니다.

## Google Sheets 연결

기존 API v7 연결을 계속 사용할 수 있습니다. 새 설치 또는 API v6 이하에서 올리는 경우:

1. 관리의 데이터 백업에서 JSON 파일을 저장하고 Google Sheets도 사본을 만듭니다.
2. 연결된 Apps Script 프로젝트의 코드를 `apps_script.gs`로 교체합니다. 기존 `doGet`/`doPost`를 중복으로 남기지 않습니다.
3. 프로젝트 설정 → 스크립트 속성에 **`FIT_API_TOKEN`**을 설정합니다. 기존 연결키는 유지하며 새 값은 32자 이상의 충분히 긴 무작위 문자열을 사용합니다. 저장소나 배포 URL에 넣지 않습니다.
4. 배포 관리 → 기존 배포 편집 → 새 버전으로 API v7을 배포합니다. 기존 배포를 편집하면 `/exec` URL을 유지할 수 있습니다.
5. 앱의 Google Sheets 연결에서 `/exec` URL과 연결키를 입력합니다. 연결키는 기기에만 저장되며 JSON 백업에는 포함되지 않습니다.
6. 기록 차이가 있으면 원본을 비교한 뒤 적용할 쪽을 선택합니다. 시트에 없는 로컬 기록을 자동 삭제하거나 일괄 덮어쓰지 않습니다.

v7 서버는 연결키 없는 요청과 구버전 쓰기 API를 거부합니다. 다른 기기도 모두 업데이트하세요.

### 거의 모든 기록이 기기에만 있다고 나올 때

관리의 연결 진단에서 연결된 스프레드시트 ID와 탭을 먼저 확인합니다. 진단은 읽기 전용입니다. 탭 누락·헤더 불일치·잘못된 파일 연결을 해결한 뒤 다시 비교합니다. 시트의 빈 응답을 로컬 데이터 삭제로 해석하지 않으며, 기존 파일과 다른 파일에 연결되면 자동 쓰기를 중단합니다. Apps Script `FIT_SPREADSHEET_ID`를 사용하는 경우 실제 기록 파일과 일치시킵니다.

### 하루 운동의 초반 세트만 시트에 있을 때

먼저 기기의 JSON 백업과 시트 사본을 보관합니다. **다시 비교 · 읽기 전용**으로 해당 날짜를 확인하고, 기기에 하루 전체 기록이 있는 경우에만 그 날짜의 **기기 기록을 시트에 적용**을 선택한 뒤 다시 비교합니다. 전송 이력이 남지 않은 과거 차이는 자동 덮어쓰지 않습니다. v7.5.7은 저장 응답 유실 후 후속 세트가 막히는 경우를 복구하지만, 실제 누락 원인은 연결 진단과 원본 비교로 확인해야 합니다.

원본 저장소 `ExLog.data`는 백업·동기화 전용으로 보존하고 추천·분석은 `ExLog.activeData`를 사용합니다. 저장소 마이그레이션과 구버전 백업 검증 코드는 기존 데이터 복구에 필요하므로 유지합니다.

## 동기화 차이가 계속 보일 때

관리 → 시트 연결 확인 → **다시 비교 · 읽기 전용**으로 현재 연결 파일을 다시 읽습니다. 인바디 숫자와 숫자 문자열, JSON 속성 순서, 내용 없는 당일 계획은 같은 값으로 비교합니다. 실제 중량·횟수·단위·메모·계획 변화는 계속 구분합니다. 읽기 실패 시 이전 차이 목록 대신 오류를 우선 표시하며, 최신 비교 전 덮어쓰기를 차단합니다.

문제가 남으면 **진단 내용 복사**로 앱·서버 버전, 연결된 파일, 기기/시트 날짜 수와 다른 항목을 확인할 수 있습니다. 연결키, 배포 URL, 세트별 값, 메모 본문은 복사하지 않습니다. 시트에 없는 기록을 삭제로 취급하거나 최초 연결의 서로 다른 기록을 자동 덮어쓰지 않습니다. 이번 프론트엔드 수정은 Apps Script 7.2.0과 호환됩니다.
